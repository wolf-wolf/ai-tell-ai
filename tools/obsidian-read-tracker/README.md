# AI Read Tracker（本地 Obsidian 插件）

为 `ai-tell-ai` Vault 记录：

- **打开次数**、**有效阅读时长**（idle 停表）、**滚动覆盖**
- **加权阅读进度**（v0.7.0）：覆盖 + 有效时长 + **Chat 提问深度** + 回访次数
- **阅读状态**：略读 / 在读 / 已读 / 精读（与进度%并存）
- **待跟进** 清单（未读 + 待深读合并，默认统计 `docs/`）
- **状态分布** / **进度分布** 条形图（v0.8.0）
- **有效阅读热力图** + **时长雷达**（v0.6.0 起默认按有效分钟，可切回打开次数）
- 滚动位置记忆、Markdown 总览导出

数据：`.obsidian/plugins/ai-read-tracker/data.json`（含 `daily` 打开次数、`dailyActive` 有效秒数）。

## 安装

```bash
bash tools/obsidian-read-tracker/install.sh
```

Obsidian 启用插件后：`Cmd+P` → **Read Tracker: 重新加载本插件**

## 使用

- **状态栏**：均进度% · 触达/待跟进 + 当前笔记
- **阅读统计总览**
  - 摘要 6 项：已触达、有效分钟、均进度、**完成率**、精读、**待跟进**
  - **阅读概览**：热力图 + 时长雷达 + **状态分布** + **进度分布**
  - 清单 Tab：**已触达 · 待跟进**（待深读优先，含类型列）
  - 热力图：默认 **有效阅读分钟**；设置可改 **打开次数**
  - 雷达：Top N **有效阅读时长**
- **待跟进**：未读 + 待深读（略读、覆盖不足等）合并为一表
- 命令 **更新总览笔记**：含待读、待深读、精读 Top、有效阅读热力

## 加权进度公式（v0.7.0）

与 [AI Cursor Chat](../obsidian-cursor-chat/) 联动：Chat 按笔记路径归档提问，Read Tracker 同步 `questionCount` 后计算：

```text
coverage  = maxScrollRatio（0–1）
time      = min(1, activeSec / estReadSec)
questions = min(1, √(questionCount) / √(targetQ))
revisit   = min(1, views / 3)
progress  = round(100 × 归一化加权和)，未手动标记已读完时最高 99%
在阅读/预览模式右侧点击「标记已读完」后，progress = 100%
```

默认权重：**覆盖 35% · 时长 30% · 提问 25% · 回访 10%**。  
**100% 仅表示你已主动确认读完**，不再由滚动/时长/提问自动推断。  
`targetQ` ≈ 每 10 分钟 1 问（按预估阅读时长与设置中的「每 10 分钟预期问题数」）。

## 设置要点

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 进度权重 | 0.35,0.3,0.25,0.1 | 覆盖/时长/提问/回访，自动归一化 |
| 每 10 分钟预期问题数 | 1 | 提问项满分阈值 |
| 热力图指标 | 有效阅读 | 或打开次数 |
| 雷达排序 | 有效时长 | 或次数 / 覆盖 |
| 已读覆盖阈值 | 85% | 判「已读/精读」状态（与进度 100% 独立） |
| 已读完悬浮按钮 | 开 | 阅读视图右侧，标记后进度才为 100% |
| 待深读覆盖上限 | 50% | 低于此进待深读 |
| idle 秒数 | 20 | 无滚动停表 |

## 版本说明

- **v0.5.0**：有效时长、覆盖、五态、待读
- **v0.6.0**：待深读、有效阅读日热力、雷达/Top 按时长、阈值可配
- **v0.7.0**：加权进度、提问数同步、Dashboard/状态栏均进度
- **v0.8.0**：待跟进合并清单、状态/进度分布图、完成率摘要
- **v0.9.0**：「标记已读完」、进度 100% 改由手动确认
- **v0.10.0**：改为阅读视图右侧悬浮按钮（不再插入正文）
- 有效时长 / `dailyActive` / 提问数从对应版本起累计，历史无法回填
