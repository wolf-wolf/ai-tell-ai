Life-Harness — Adapting the Interface, Not the Model（arXiv:2605.22166）GitHub

确定性 Agent 环境（τ-bench、AgentBench 等）失败常源于「模型—环境接口」不匹配，而非单纯能力不足；传统做法微调权重或改环境规则，成本高且难迁移。

在<strong>冻结</strong> LLM 与<strong>不变</strong>评测环境前提下，从训练轨迹抽取重复失败，演化四类 runtime 干预——环境合约（h3）、程序技能（h5）、动作实现（h2）、轨迹调节（h4）；评测阶段固定 harness，测未见任务。 7 个基准 × 18 骨干共 <strong>126</strong> 组设定中 <strong>116</strong> 组提升；平均相对增益 <strong>88.5%</strong>；仅用 Qwen3-4B-Instruct 轨迹演化的 harness 可迁移到 <strong>17</strong> 个其他模型。

  • 把「Agent 工程」从 Prompt 调参推进到可版本化的 harness 资产，与 Claude Code skills / revfactory 团队拓扑互补。
  • 支持「小模型 + 强 harness」路线，降低对单一 frontier 模型的依赖。
  • 生产落地应开始记录失败轨迹分类（合约违反 vs 动作解析 vs 轨迹发散），作为 harness 演化输入。
  • 与 OpenAI Codex 税务案例同构：二者都强调接口层迭代，差异在于 Life-Harness 免训练、Codex 案例偏代码级 eval 循环。
