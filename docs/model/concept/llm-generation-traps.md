# 模型的陷阱 (LLM Generation Traps)

> [!tip] 核心本质
> 模型的陷阱，是自回归生成与 RLHF 对齐在机制上催生的一系列违背专家直觉的输出惯性——结构对称、Token 均分、格式强迫症与「端水」全面性。人类思考是高度非对称（Spiky）的；模型概率引擎倾向平滑（Smooth）。若不在 Prompt、Workflow 与认知层建立对抗约束，优化提示词也只能得到工整但无认知张力的「大模型八股文」。

## 生命周期与演进

**当前定位**：长文与复杂 Agent 输出的系统性风险；与 [[skill-engineering]]、[[prompt-engineering]] 的硬约束设计直接相关。

**预期寿命**：随架构与对齐演进，表现形式会变，但「平滑 + 讨好标注」张力长期存在。

**近期演进**：Reasoning 模型、分治生成、Reviewer Agent 成为工程标配缓解手段。

**终极威胁**：对齐目标改为「尖锐、可验证」且训练数据覆盖专家风格后，部分陷阱减弱——短期仍须工程对抗。

## 核心原理

为什么模型写出来的文章总让人觉得“每个段落一样长，什么都说了但什么都没深入”？我们需要深入其底层的概率分布与对齐策略，拆解三大隐性逻辑陷阱。

### 1. 结构对称性偏置 (Symmetry Bias)

大模型在生成长文本时，其注意力机制（Attention Mechanism）会受到前置文本结构的强烈影响。

*   **物理现象**：当提示词或已生成的前文中出现了一个结构化的列表（如 1、2、3、4），模型在预测后续 Token 时，其概率分布会向着“补齐这个网格”的方向倾斜。它在内部会将这四个要点视为“同等权重的兄弟节点”。
*   **结果代价**：这导致了严重的 Token 预算均分。如果第 1 节（简单概念）写了 200 字，模型在写第 3 节（极其复杂的底层源码流转）时，也会隐性地试图在 200 字左右收尾。为了凑字数，它会在简单概念里塞入廉价的比喻；为了克制字数，它会在复杂原理中删去关键的数据结构。

### 2. 模式匹配与上下文强迫症 (Pattern Completion)

自回归模型的唯一法则是“Predict the next token”。这意味着**前文不仅决定了内容，更死死绑定了格式**。

*   **物理现象**：假设文章第一节包含了一个 Markdown 表格，当模型生成到第二节时，即使这一节的内容完全不需要表格，Transformer 捕捉前文特征后，仍会赋予 `|` 和 `-` 等制列表符极高的生成概率。
*   **结果代价**：模型变成了没有灵魂的排版机器。它不再思考“这里需不需要一张架构图”，而是思考“为了保持与上一段的结构一致，我必须在这里捏造一个流程图”。这导致了过度排版，破坏了人类阅读时自然的心流（Flow）。

### 3. RLHF 带来的“端水效应” (Helpfulness Penalty)

RLHF（基于人类反馈的强化学习）的初衷是让模型变得安全且有用，但副作用是极度抹杀了模型的“观点锋芒”。

*   **物理现象**：在 RLHF 阶段，覆盖全面、两面兼顾的回答（“一方面...另一方面...总之...”）往往能得到标注员的高分。因此，模型的权重被更新为极度厌恶“偏激”或“非对称”的论述。
*   **结果代价**：当要求模型对比两种技术路线（例如 Tool vs Skill）时，人类专家会直接用一句大实话指出前者的致命缺陷。而模型受到奖励函数（Reward Function）的约束，会强行写出“两者各有千秋，在不同场景下都有应用价值”的废话。它宁愿牺牲认知增量，也要换取安全得分。

## 实践与应用

要彻底解决被写进大模型底层骨架里的陷阱，单纯在对话框里加上一句“请重点写第一段”是远远不够的。在实际的 Agent 工程和高级 Prompt 设计中，我们通常需要在三个层级上建立“防御机制”，通过物理干预强制打破这种平庸与对称：

### 1. 提示词层（Prompt）：强制的物理破坏

在这个层级，核心思路是**用极端的约束条件，去对冲模型的平滑惯性**。

-   **设立反 RLHF 人设（Polarized Persona）**：不要只说“你是一个专家”，这会触发它“面面俱到”的 RLHF 预设。必须在 System Prompt 中硬编码极端的风格约束：“_你是一个极其主观、犀利的资深架构师。严禁使用‘一方面/另一方面’、‘各有千秋’等端水废话。在对比技术时，必须明确选定一个胜出者，并对失败者进行致命的物理级批评。_”
-   **定量的非对称分配（Asymmetric Token Budgeting）**：用精确的数字斩断对称性。比如：“_本文分为 4 节。第 1 节字数不得超过 50 字；第 3 节必须占据全文 80% 的篇幅。_”
-   **格式的显式熔断**：在要求模型接着上文写时，强行插入打断指令：“_警告：上一节使用了表格，本节严禁使用任何表格和无序列表，必须用纯连贯的段落推演。_”

### 2. 编排层（Workflow）：物理隔离与分治（终极解法）

只要在同一个上下文窗口里，模型就一定会受到“上下文强迫症”的绑架。最彻底的解法是**切断上下文**。

-   **骨架与血肉分离（Map-Reduce / 树形生成）**：这是目前生成长文本与复杂代码的终极范式。第一步，只让模型输出大纲（骨架）；第二步，**开出多个完全独立的全新上下文窗口（Session）**，把大纲的不同小节分别发给没有历史记忆的模型去生成。因为它们互相看不见对方生成了什么格式，就从根本上消灭了“为了对称而排版”的陷阱。最后再用代码把结果缝合。
-   **对抗生成与批判路由（Adversarial Review）**：生成初稿后，不是直接输出，而是丢给另一个加载了“找茬 Prompt”的 Reviewer Agent。它的唯一任务就是寻找陷阱：“_检查这篇草稿，圈出所有‘为了对称而硬凑的排版’和‘没有实质信息的比喻’，将其直接删除。_”

### 3. 认知层：把“什么是好”显式化（Few-Shot 注入）

大模型自己不知道什么是“有张力的好文章”，它只知道“高概率的常规文章”。

-   **对比式少样本注入（Contrastive Few-Shot）**：在 Prompt 中直接给它展示一个“错误示范”（例如四个段落一样长、满篇粗体字的 AI 八股文），再给它展示一个“正确示范”（前言只有一句话，核心原理论述占了三页纸的人类专家博客）。明确告诉它：“_绝对不要像 A 这样写，必须像 B 这样写。_”
