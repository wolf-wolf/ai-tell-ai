# LLM（大语言模型）

> [!tip] 核心本质
> 大语言模型（LLM）是用海量文本训练的自回归语言模型——训练目标只有一个：给定前文，预测下一个 token。这个目标看似简单，却逼着模型把语言规律、世界知识和逻辑推理都压缩进参数里，涌现出看起来像「理解」的能力。但这个设计也决定了它的硬限制：推理时无状态、无搜索、无持久记忆，只是在参数空间里做高维度的模式延续；知识截止于训练数据，预测不确定时会自信地编造。若没有理解这些边界，后续所有基于 LLM 的工程设计都会建立在错误的假设上。

适合作为**模型层入口**的读者：已听过「大模型」，要在搭 [[agent]]、[[rag]] 或选型前弄清**能力从哪来、硬边界在哪**。读完 [[#2 边界：LLM 与 Agent、RAG、世界模型|§2]] 能判断该补外部循环还是换架构；[[#6 核心局限与工程对策|§6]] 给出对策链到专文。预训练目标与损失细节见 [[token-prediction]]；缩放与涌现见 [[scaling-laws]]、[[emergence]]。

*检索说明：GPT-3 [Brown et al. 2020](https://arxiv.org/abs/2005.14165)、Scaling Laws [Kaplan et al. 2020](https://arxiv.org/abs/2001.08361)、DeepSeek-R1 [2025](https://arxiv.org/abs/2501.12948)（观测 2026-06-14）。*

## 生命周期与演进

**当前定位**：第一类智能基础设施。主干能力（语言理解、代码生成、多步推理）已充分验证并 API 化；竞争重心转向推理效率（推理模型）、多模态融合与小模型质量。

**预期寿命**：长期。「在海量数据上训练大参数模型」的范式短期不会被颠覆；架构细节（混合专家 MoE、线性注意力、更长上下文）持续演化，但 [[transformer]] + 自回归生成的核心地位稳固。

**近期演进**：推理/thinking 模型（o1、o3、DeepSeek-R1、Claude thinking）在推理时分配可控计算预算做[[chain-of-thought|链式思考（chain-of-thought）]]，把「推理能力」从参数量部分解耦；小模型质量跃升（Phi-4、Qwen3 等 7B 在部分基准上接近早期 70B）；多模态（视觉、音频、视频）成为默认能力而非可选扩展。

**终极威胁**：「预测下一个 token」训练目标可能被「预测下一个动作/状态」取代（[[world-model]] 方向）；更近期是推理模型 + 验证器（generate-and-verify）在逻辑任务上逼近形式化方法，使纯语言模型角色收窄为「生成草稿」。

## 1 问题语境：别把它当数据库

常见误判：把 LLM 当成**可查事实的数据库**、**记得住上次对话的助手**，或**会在内部搜索正确答案再输出**的系统。实际上每次 API 调用默认**无状态**——模型只是在当前上下文里续写高概率 token 序列；「知道」的事实是训练时压进权重的统计关联，不是运行时检索。

因此工程上几乎总要外接：**[[rag]]** 补知识与时效、**[[memory]]** 补跨会话状态、**[[agent]]** 外循环补工具与规划。不理解这一点，会把幻觉、知识过期、长上下文失效全怪到「模型不够聪明」。

## 2 边界：LLM 与 Agent、RAG、世界模型

**表 1 — 易混分工（读 LLM 时先挂这张表）**

| 维度 | LLM 本体 | 典型外接 |
| --- | --- | --- |
| **推理核心** | 单轮/多轮文本续写 | [[agent]] 编排工具与步进 |
| **知识** | 训练截止 + 参数内压缩 | [[rag]] 检索注入 |
| **状态** | 无跨请求记忆 | [[memory]]、上下文工程 |
| **事实性** | 高概率续写 ≠ 真 | [[hallucination]] 专文、校验器 |
| **世界动力学** | 隐式文本关联 | [[world-model]] 显式状态预测 |

LLM 是 **Agent 的大脑切片**，不是完整 Agent。RAG 解决「此刻该看到什么文档」，不替代「如何把文档编译成可维护知识库」（见 [[llm-wiki-overview]]）。

## 3 训练栈：从续写到听指令

预训练的本质是**有损压缩**——为准确预测下一个 token，模型必须学会语法、语义、事实与推理，否则损失下不去。这些能力多为完成 [[token-prediction]] 目标**顺带习得**，非单独设计（详见 [[emergence]] 与度量争议）。

**表 2 — 训练三阶段（机制分工，细节见专文）**

| 阶段 | 数据与目标 | 读者应记住 |
| --- | --- | --- |
| **预训练** | 互联网文本/书籍/代码；下一 token 预测 | 世界知识压进参数；有知识截止 |
| **监督微调（SFT）** | 指令→回答对 | 从「续写」变成「执行指令」；见 [[sft]] |
| **对齐** | 人类/AI 偏好 | 更安全、更符合偏好；见 [[rlhf]]、[[llm-generation-traps]] |

**[[emergence|涌现能力（Emergent Abilities）]]**：规模跨过阈值后，少样本提示、链式思考、复杂指令等下游表现可能**看似**跃迁——不能靠小模型外推（[Wei et al. 2022](https://arxiv.org/abs/2206.07682)；争议见 [[emergence]] §4）。算力与数据配方见 [[scaling-laws]]、[[training-data]]。

## 4 推理时生成：自回归与采样

模型不是「想好整句再输出」，而是**自回归**逐 token 滚动：预测第 1 个 token → 拼入上下文 → 再预测第 2 个，直至终止符；生成过程中**默认不回头改**已输出内容。

对下一个 token 输出的是**概率分布**。常用解码参数：

| 参数 | 含义 | 效果 |
| --- | --- | --- |
| **温度（temperature）= 0** | 取概率最高 token | 确定性强，适合代码/JSON；易重复 |
| **温度较高（如 1.5）** | 拉平分布，低概率 token 也可被选 | 多样、易发散 |
| **核采样（top-p）** | 只在累积概率达 p 的 token 池内采样 | 兼顾质量与多样性 |

同一 prompt、相同温度下输出可能不同——来自**采样随机性**，不是「模型在思考不同答案」。

## 5 推理时计算与规模选型

### 5.1 推理模型（reasoning / thinking）

传统 LLM 每个 token 消耗的计算大致相同。2024 年后的**推理模型**（o1、o3、DeepSeek-R1、Claude thinking）在给出最终答案前，先消耗预算生成**链式思考**（部分产品对用户隐藏），在数学、逻辑、代码等多步任务上常优于同参数量普通模型。

**本质变化**：推理能力从「训练时全压进参数」部分转移到「推理时动态展开」——与 [[chain-of-thought]]、[[rlvr]] 等路线相关；开源代表见 [DeepSeek-R1](https://arxiv.org/abs/2501.12948)。

### 5.2 参数量与选型

参数量与能力**非线性**；存在规模相关的跃迁叙事，但不宜把 benchmark 断崖等同于「智能相变」（[[emergence]]）。

**表 3 — 量级直觉（非承诺阈值，随训练配方变化）**

| 参数量级 | 常见能力轮廓 |
| --- | --- |
| ~1B | 基本流畅、简单问答 |
| ~7B | 指令遵循、轻量推理 |
| ~70B | 复杂推理、代码、多步任务 |
| 数百 B+ | 前沿综合任务；具体领域仍须评测 |

「越大越好」在 2024 年后已不绝对：Phi-4、Qwen3-7B 等在部分基准上超过早期 GPT-3.5（175B）——**数据质量、训练与对齐**常与参数量同等重要（[GPT-3](https://arxiv.org/abs/2005.14165)、[[scaling-laws]]）。

| 选择 | 适合场景 |
| --- | --- |
| 大模型 | 任务复杂、多领域迁移、上下文利用要求高 |
| 小模型 + 精调 | 延迟/成本敏感、垂直场景、私有化 |
| 推理模型 | 数学/逻辑/长链自检；愿付推理 token 成本 |

## 6 多模态与核心局限

### 6.1 多模态

主流 LLM 已支持图片、PDF、音频（部分）、视频（部分）输入：其他模态特征被编码为 token，与文本一并进入 [[transformer]]。工程上不宜再假设输入恒为纯文本——截图分析、文档理解常可直接交给模型，但仍受幻觉与截止日约束。

### 6.2 核心局限与工程对策

**表 4 — 局限根因与对策（LLM 枢纽速查）**

| 局限 | 根因 | 工程对策 |
| --- | --- | --- |
| **[[hallucination\|幻觉]]** | 续写高概率 token，非事实检索 | [[rag]]、工具、输出校验 |
| **知识截止** | 训练数据时间截点 | [[rag]]、实时工具 |
| **无状态** | 请求间不保留记忆 | [[memory]]、[[context-engineering]] |
| **上下文上限** | [[context-window]] 有限；Lost in the Middle | 精准注入、分块、摘要 |
| **生成偏置** | [[rlhf]] 等对齐副作用 | [[llm-generation-traps]] |

## 要点收束

- LLM = **下一 token 预测**驱动的自回归模型；「理解」多为压缩与规模下的涌现表象。
- 默认**无状态、非检索、会幻觉**——Agent/RAG/Memory 是补缺口，不是可选项。
- 训练栈：**预训练 → SFT → 对齐**；细节分散在 [[sft]]、[[token-prediction]]、[[rlhf]] 等专文。
- **推理模型**用推理时 token 预算换多步能力；选型须同时看参数量、配方与评测。
- 局限表应对策已链到 [[hallucination]]、[[context-window]]、[[agent]] 等下游设计。
