# LLM（大语言模型）

> [!tip] 核心本质
> LLM 是一个用海量文本训练的自回归语言模型——训练目标只有一个：给定前文，预测下一个 token。这个目标看似简单，却逼着模型把语言规律、世界知识和逻辑推理都压缩进参数里，涌现出看起来像「理解」的能力。但这个设计也决定了它的硬限制：推理时无状态、无搜索、无持久记忆，只是在参数空间里做高维度的模式延续；知识截止于训练数据，预测不确定时会自信地编造。若没有理解这些边界，后续所有基于 LLM 的工程设计都会建立在错误的假设上。

## 生命周期与演进

**当前定位**：第一类智能基础设施。主干能力（语言理解、代码生成、多步推理）已充分验证并 API 化；竞争重心转向推理效率（reasoning 模型）、多模态融合与小模型质量。

**预期寿命**：长期。「在海量数据上训练大参数模型」的范式短期不会被颠覆；架构细节（MoE、线性注意力、更长 context）持续演化，但 transformer + 自回归生成的核心地位稳固。

**近期演进**：reasoning/thinking 模型（o1/o3、DeepSeek-R1、Claude 3.5/3.7 Sonnet thinking）在推理时分配可控计算预算做链式思考，把「推理能力」从参数量部分解耦；小模型质量跃升（Phi-4、Qwen3 等 7B 模型接近早期 70B 水平）；多模态（视觉、音频、视频）成为默认能力而非可选扩展。

**终极威胁**：「预测下一个 token」这个训练目标本身可能被「预测下一个动作/状态」取代（world model 方向）；更近期的威胁是 reasoning 模型 + 验证器组合（generate-and-verify）在逻辑推理类任务上逼近形式化方法的精度，使纯语言模型的角色收窄到「生成草稿」。

## 预训练：世界知识的有损压缩

预训练的本质是「有损压缩」——模型为了准确预测下一个 token，必须学会语法、语义、事实知识和逻辑推理，否则预测质量上不去。这些能力不是专门设计的，是为了完成预测目标**顺带涌现**的。

```
预训练（Pre-training）
  数据：互联网文本、书籍、代码（万亿级 token）
  目标：给定前文，预测下一个 token
  结果：语言规律、世界知识、逻辑推理都被压进参数

指令微调（SFT）
  数据：人工标注的「指令 → 回答」对
  目标：从「续写文本」变成「理解并执行指令」

对齐（RLHF / DPO）
  目标：让输出更安全、更符合人类偏好
  代价：引入对称性偏置与「端水效应」——见 [[llm-generation-traps]]
```

**[[emergence|涌现能力（Emergent Abilities）]]**：参数量和数据量超过临界点后，模型突然能做之前完全不会的事——few-shot 学习、chain-of-thought 推理、跨领域迁移。这不是线性增长，而是相变式跃升（存在度量争议，见该文 §4）。

## 推理时的生成过程

理解 LLM 如何「输出一个字」，是理解其行为的前提。

**自回归展开**：每次调用，模型不是「想好整句话再说出来」，而是逐 token 生成——预测第 1 个 token，把它拼进去，再预测第 2 个，循环直到生成终止符。整个回答是一步步「滚动」出来的，没有回头修改。

**采样与 Temperature**：模型对下一个 token 输出的是概率分布，不是确定的单一答案。

| 参数 | 含义 | 效果 |
| --- | --- | --- |
| **Temperature = 0** | 始终取概率最高的 token | 确定性强，适合代码/JSON；容易重复自己 |
| **Temperature 高（如 1.5）** | 平摊概率分布，低概率 token 也有机会被选 | 创意性强，输出多样；容易发散、不可控 |
| **Top-p（核采样）** | 只从累积概率达 p 的 token 池里采样 | 兼顾多样性与质量 |

**同一 prompt，相同 temperature 下每次输出可能不同**，这是采样随机性导致的，不是「模型在思考不同答案」。

## Reasoning 模型：推理时计算的革命

传统 LLM 每个 token 消耗的计算几乎相同，「想难题」和「说废话」代价一样。2024 年后涌现的 **reasoning/thinking 模型**（o1、o3、DeepSeek-R1、Claude thinking）改变了这一点：

- 在生成最终答案前，先输出一段「思考过程」（chain-of-thought），这段思考不给用户看，但会消耗 token 预算
- 可以设置「thinking budget」控制花多少计算在推理上
- 在数学、逻辑、代码等需要多步推理的任务上，比同参数量的普通模型提升显著

**本质变化**：把推理能力从「训练时压进参数」部分转移到「推理时动态展开」——让模型在生成阶段自己做草稿、验证、修正，而不只靠参数里的静态模式。

## 参数量与能力

参数量不是线性提升能力，而是存在**能力跃迁点**：

| 参数量级 | 典型能力 |
| --- | --- |
| ~1B | 基本语言流畅，简单 QA |
| ~7B | 指令遵循，简单推理 |
| ~70B | 复杂推理，代码生成，多步任务 |
| ~700B+ | 接近或超过人类专家水平（特定领域） |

「大模型好、小模型差」这个直觉在 2024 年后已不准确。Phi-4、Qwen3-7B 在很多基准上超过早期 GPT-3.5（175B）——数据质量和训练方式的影响已超过参数量本身。

| 选择 | 适合场景 |
| --- | --- |
| 大模型 | 任务复杂度高、需要强推理或多领域迁移 |
| 小模型 + 精调 | 延迟/成本敏感、垂直场景、可私有化部署 |
| Reasoning 模型 | 逻辑推理、数学、需要自我校验的长链任务 |

## 多模态

现代主流 LLM 已原生支持多模态输入：图片、PDF、音频（部分），以及视频（部分）。底层实现是把其他模态的特征编码成 token，与文字 token 一起进入 transformer。

**对工程的影响**：Skill / RAG / Agent 设计时，不能再假设输入一定是纯文本；工具调用、截图分析、文档解析等场景可以直接交给模型处理，无需额外 OCR 步骤。

## 核心局限

| 局限 | 根因 | 工程对策 |
| --- | --- | --- |
| **幻觉（Hallucination）** | 生成的是「高概率的 token 序列」，不是事实检索；知识不足时仍会自信续写 | [[hallucination]]、RAG、工具调用、输出校验 |
| **知识截止日期** | 训练数据有时间截点，之后发生的事模型不知道 | RAG 注入实时信息 |
| **无状态** | 每次 API 调用独立，不自动记忆上次对话 | 外部 Memory、context 管理——见 [[memory]] |
| **上下文长度限制** | context window 有上限；过长时中间段内容被忽略（Lost in the Middle） | RAG 精准注入、分块处理——见 [[context-window]] |
| **生成行为偏置** | RLHF 引入对称性惯性与「端水效应」 | 见 [[llm-generation-traps]] |
