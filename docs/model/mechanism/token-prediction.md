# Token 预测（下一个 Token 预测）

## ⚡ 30 秒速览

LLM 的核心训练任务只有一件事：给定前面所有 token，预测下一个最可能出现的 token。
这个看似简单的自监督任务不需要人工标注，却让模型从海量文本中涌现出语法、常识、推理等复杂能力。
记住：把「猜下一个词」做到极致，就什么都会了——这就是 LLM 能力的来源。

---

## 🧠 深入理解

### 背景：为什么选这个训练目标

训练一个 AI 模型，需要一个可量化的目标函数。对于语言来说，有几种可能：

- 判断句子是否语法正确？需要人工标注语法规则
- 理解句子含义？「含义」本身难以量化
- 预测下一个词？**无限的自然文本天然就是训练数据，不需要任何标注**

这就是 Next Token Prediction 的精妙之处：互联网上万亿字的文本，每一句话都可以直接用来训练——把句子前半段作为输入，后面的词作为标签，模型自动学习。

这种训练方式叫**自监督学习（Self-supervised Learning）**，无需人工标注，让 LLM 能在前所未有的规模上训练。

### Token ≠ 单词

模型处理的基本单位是 **token**，不是单词。Token 是通过子词分词（BPE / WordPiece 等算法）切分的：

```
「unhappiness」→ [「un」, 「happiness」]
「ChatGPT」  → [「Chat」, 「G」, 「PT」]
「你好」     → [「你」, 「好」]（中文通常一字一 token）
「2024年」   → [「2024」, 「年」]
```

为什么不直接用单词？
- 词汇表会无限大（每个新词、拼写错误都要收录）
- 子词能组合出未见过的词：「un-」+ 任何词根
- 控制词汇表大小，约 32K-100K token 就能覆盖所有常见情况

**实际影响**：1 个英文单词 ≈ 1.3 个 token；1 个中文字 ≈ 1-2 个 token。这是为什么 context 窗口用 token 计数，不用字数。

### 核心机制：生成的本质是采样

训练完成后，模型对「下一个 token」输出的不是一个确定答案，而是**整个词汇表上的概率分布**：

```
输入：「今天天气很」
模型输出（部分）：
  「好」  → 0.45
  「差」  → 0.20
  「热」  → 0.15
  「冷」  → 0.10
  其他   → 0.10
```

从这个分布中**采样**一个 token，再把它拼回输入，继续预测下一个……这就是 LLM 生成文本的全过程。

**Temperature 的作用**：
```
temperature = 1.0（默认）：按原始概率采样
temperature = 0.1（低温）：「好」的概率被放大到接近 1，输出非常确定/保守
temperature = 2.0（高温）：概率分布被压平，随机性增加，输出更有创意/更乱
temperature = 0（贪婪）：永远选概率最高的词，输出完全确定但可能单调
```

**Top-p（核采样）的作用**：
只在「概率累积到 p 为止的 token 集合」中采样，裁剪掉长尾低概率词。
```
top-p = 0.9：只考虑前 90% 累积概率的候选 token
→ 既避免选到奇怪词，又保留了合理的多样性
```

### 为什么简单目标能产生复杂能力

这是最反直觉也最迷人的地方：**为了预测下一个词，模型必须学会一切**。

要预测「巴黎是法国的___」后面是「首都」，模型必须知道地理事实。
要预测一段对话中下一句合理的回应，模型必须理解对话结构和社交常识。
要预测代码的下一行，模型必须理解编程语言语法和逻辑。

当模型在足够大的数据规模和参数量上训练后，这些能力开始**涌现（Emergence）**——在某个规模阈值后突然出现，而非线性增长。这正是 Scaling Law 的核心发现。

### 为什么 LLM 会幻觉

根本原因在于训练目标本身：

**模型学的是「什么词在这个语境下合理地出现在下一个」，而不是「这个陈述在现实中是否为真」。**

```
输入：「量子力学的奠基人是___」
模型在做的：根据训练数据中类似语境，
           「玻尔」「海森堡」「薛定谔」「爱因斯坦」
           都是在这种语境下高频出现的名字
           → 选一个概率高的输出
           
模型没有在做的：查询一个「谁是量子力学奠基人」的事实数据库
```

所以 LLM 输出的是**统计上合理的文本**，不是**事实检索的结果**。当训练数据中某个错误陈述出现频率高，或某个问题的答案模糊，模型会自信地输出错误答案。

这是 RAG 存在的根本原因之一：用检索到的真实文档来锚定生成，减少纯靠统计猜测带来的错误。

## 💡 示例

**感受 temperature 的差异：**

```
输入：「写一句诗的开头：春风___」

temperature = 0（贪婪）：
  → 「吹绿了大地」（最常见，符合训练数据高频模式）

temperature = 0.7（常用值）：
  → 「拂过窗棂，带来远山的消息」（自然，有变化）

temperature = 1.5（高温）：
  → 「把月亮切成了三角形」（有创意，但可能语义奇怪）
```

**Token 切分的实际感受：**
```
「I can't believe it!」

GPT tokenizer 切分：
['I', ' can', "'t", ' believe', ' it', '!']
= 6 个 token

「今天天气真好」
= ['今', '天', '天', '气', '真', '好']  
= 6 个 token

注意：同样 6 个 token，英文表达了 5 个英文词，中文只有 6 个字
→ 中文处理效率相对低，消耗更多 token
```

## ⚠️ 常见误区

- **误区 1：LLM 在「思考」答案然后输出。** 错。LLM 是逐个 token 生成的，每次只看当前 context 决定下一个词，没有「先想好再说」的过程（Chain of Thought 在一定程度上模拟了这个，但那是输出过程中的思维展开，不是输出前的计划）。

- **误区 2：temperature = 0 是最好的设置。** 对于事实性问答，低 temperature 稳定性好；但对于创意写作、代码生成（需要探索多种方案），完全贪婪解往往质量差，适度随机性反而更好。

- **误区 3：LLM 输出有信心的内容就是真的。** LLM 的「信心」体现在语气，而语气来自训练数据的表达风格，和内容真实性无关。模型说「当然是……」和说「可能是……」的置信度差异不来自事实核查，而来自语言模式。

- **误区 4：token 就是字。** 英文一个词可能被切成多个 token，中文一个字通常是一个 token，但复杂汉字可能是两个 token。永远用 token 而非字数来估算 context 用量。

## 💬 我的理解

> 理解 LLM 的幻觉，要从这里开始：它不是「知道但说错了」，而是「从来不是在查事实，只是在生成统计上合理的下一个词」。这是一个根本性的认知校准。
> 和 Transformer 的衔接：Transformer 是执行这个预测任务的架构——每次预测下一个 token，都是在跑一次完整的 Transformer 前向传播。理解了这两个原理，LLM 的行为（为什么有时聪明、为什么会幻觉、为什么 temperature 有效）就都可以从第一原理推导出来。
