# 训练数据与语料

> [!tip] 想一想
> **为什么 GPT-4 会写代码、会做数学、会讲笑话，但就是不知道上周发生了什么？**
>
> *因为它只见过训练数据里有的东西，训练数据截止之后的世界对它来说不存在。*
>
> 训练数据是模型能力的上限，模型学到什么、学不到什么，完全由数据决定。

---

## 🧠 深入理解

### 没有训练数据，模型什么都不是

[[token-prediction|Token prediction]] 本身只是一个数学框架——预测下一个 token 的概率分布。这个框架什么都不知道，能力从哪来？全从数据来。

从第一性原理想这个问题：你要让一个系统学会"人类语言里的规律"，最直接的方式是什么？给它看足够多的人类语言，让它从中自动归纳规律。这就是预训练的本质——用海量文本让模型拟合语言的统计规律，语言背后的知识、推理、风格全都隐含在这些统计规律里。

所以**数据的边界就是模型能力的边界**。数据里没有的语言，模型不会说；数据里没有的知识，模型不知道；数据里的偏见，模型会学进去。

### 数据从哪来，决定了模型擅长什么

预训练数据通常来自几个来源，各有侧重：

| 来源 | 典型内容 | 影响 |
|------|---------|------|
| 网页爬取（Common Crawl 等）| 新闻、博客、论坛 | 覆盖广，但质量参差不齐 |
| 书籍 | 文学、教材、专著 | 长文本推理能力，语言质量高 |
| 代码仓库（GitHub 等）| 各类编程语言 | 代码能力、结构化推理 |
| 学术论文（arXiv 等）| 数学、物理、CS | 科学推理、符号处理 |
| 网页过滤精选 | 高质量人工筛选文本 | 语言质量的天花板 |

一个模型的代码能力强，大概率是训练数据里代码比例高；数学推理差，大概率是高质量数学文本不够。能力的差异几乎都能在数据分布上找到原因。

### 数据质量 vs 数据量

直觉上以为数据越多越好，但这个直觉在 2023 年之后被系统性修正了。

**数据质量的影响远大于数据量。** Phi 系列模型（微软）用远少于 GPT-4 的数据量，靠高质量的"教科书式"合成数据，在很多任务上达到了远超数据量预期的性能。Llama 3 的训练数据经过了严格的质量过滤，同等参数量下效果明显好于数据更多但质量更混杂的前代。

从数据构成上看，**数据分布比总量更关键**——多语言比例、领域分布、文本长度分布都会影响最终能力的形态。

### 训练数据截止日期

模型只知道训练数据截止日期之前的事，这不是技术缺陷，是预训练范式的必然结果。

解决方案有两个：一是用 RAG 在推理时注入新信息，二是持续更新训练数据重新训练（成本极高）。[[rag|RAG]] 是目前最常用的方案，但它解决的是"查询实时信息"的问题，不能改变模型的内置知识结构。

### 边界

训练数据能决定的：模型的知识范围、语言能力、推理风格、内置偏见。

训练数据决定不了的：模型在推理时的上下文（那是 [[context-window|context window]] 的事）、模型对新信息的获取（那是 RAG 的事）、模型是否"听话"（那是 [[rlhf|RLHF]] 的事）。

## 💡 示例

为什么同样是 LLM，有的擅长写 Python，有的擅长写法律文书？

看训练数据就知道了：

- GitHub Copilot 背后的模型，训练数据里代码占比极高，自然擅长代码
- Harvey（法律 AI）用的是大量法律文书、判例精调，自然擅长法律语言
- 通用模型（GPT-4、Claude）数据来源最广，能力最均衡，但在某个垂直领域不如专门模型

没有神秘的"智能"，只有数据分布的映射。

## ⚠️ 坑与误区

"更大的模型一定更强"是常见误解。参数量决定模型的容量上限，但实际能力由训练数据和训练方式共同决定。一个参数量小但数据质量高的模型，可以在很多任务上打败参数量大但数据混杂的模型。

"知识截止日期之后的事模型完全不知道"也不完全准确。如果某件事在截止日期之前已经有预测或讨论（比如某项技术的发展趋势），模型可能有间接认知。但具体事件，比如截止后发生的新闻，确实是盲点。

| 风险 | 表现 | 应对 |
|------|------|------|
| **数据偏见被放大** | 模型在某类群体的问题上回答失准 | 了解模型的训练数据构成；用评估集专门测试偏见场景 |
| **截止日期幻觉** | 模型用过时信息回答当前问题 | 对时效性强的问题用 RAG 注入最新信息；提示模型说明知识截止日期 |
| **数据污染** | 测试集数据泄漏进训练集，评估结果虚高 | 核查基准测试是否在模型训练截止日期之前公开 |
