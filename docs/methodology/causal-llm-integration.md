# 因果推理与 LLM 的集成路线

> [!tip] 核心本质
> LLM 的预训练目标是预测下一个 token，这个目标天然倾向于拟合「共现」而非「因果」——模型容易把高频共现当成因果关系，把干预效果和观察相关性混用。两条集成路线分别从不同方向修补这个缺陷：内部路线改写模型权重里的推理归纳偏置；外部路线在推理时注入已知因果结构，绕开权重层面的局限。没有这两条路线的任何一条，要么需要接受「模型因果推理靠运气」，要么需要在每次使用时手动注入因果约束——两者都不可规模化。

## 生命周期与演进

**当前定位**：活跃研究前沿，2025-2026 年从「提示技巧」升级为「训练范式 + 系统架构」。内部路线以 ICML/ICLR 论文为主，外部路线已有生产部署案例，但工程成熟度参差不齐。

**预期寿命**：mid——具体框架（CausalRAG、SCM-GRPO 等）会快速演化，但「内部 vs 外部」的路线划分和各自的核心权衡是稳定的判断框架，可用于评估未来出现的新方法。

**近期演进**：两条路线正在出现融合趋势——用内部路线训练出更强的因果推理底座，再用外部路线注入领域特定的因果结构。CIVeX 的「工具调用 = 因果干预」思想开始影响 Agent 框架设计。

**终极威胁**：若未来大模型在预训练阶段就能从干预数据（而非纯观察数据）中学习，内部路线的成本会大幅下降，外部路线的必要性会缩小到「需要实时更新的领域知识」场景。

## 概念示意

集成路线建立在 [[causal-chain]] 的因果链分析之上。基础结构（相关 vs 因果、三层链、正向/逆向推演）见 [[causal-chain#概念示意]]。

## 内部集成路线：重塑权重里的因果归纳偏置

内部路线的核心问题：**标准预训练数据是观察数据，无法区分相关和因果**，模型从中学到的是高频共现模式。三种方法各自从不同角度切入。

### 公理式训练（Axiomatic Training）

ICML 2025 提出的范式。不提供因果发生时的数据值，而是提供**因果公理本身的多次示例**，让模型内化公理而不是记忆实例。

```
训练输入（传递性公理示例）：
  A → B, B → C  ⟹  A → C   （3 节点链）
  M → N, N → O  ⟹  M → O
  ...（大量不同变量名的同结构示例）

评估（从未见过的图结构）：
  A → B, B → C, C → D, D → E  ⟹  A → E?   （7 节点链）
  图中有分支、边方向扰动？
```

一个 67M 参数从头训练的模型，在 d-separation 推理上超过了 GPT-4 和 Gemini Pro——核心原因不是参数量，而是训练目标精准对准了因果公理的结构。

关键工程发现：
- **训练集多样性 > 数量**：只在简单有向链上训练，泛化会失败；加入边方向扰动后，泛化能力显著提升
- **位置编码选型**：RoPE（旋转位置编码）在因果结构泛化上最优，其次是无位置编码，标准绝对位置编码最差

反事实检验：如果只给「知识」而不给「公理示例」，模型背下的是因果词汇而非推理能力，遇到新图结构就失效——这是区分「因果鹦鹉」和「真正因果推理」的核心区别。

### SCM-CoT + RL 对齐

把结构因果模型（SCM / DAG）嵌入 Chain-of-Thought 的训练目标，再用强化学习做对齐。这条路线有三个关键工作：

**Causal-CoT**（ICLR 2026 在审）：在推理阶段把线性 CoT 改造为图结构推理。

```
标准 CoT：
  步骤 1 → 步骤 2 → 步骤 3 → 答案

Causal-CoT 三阶段：
  (1) DAG 构图：从问题 context 提取因果图
  (2) 图增强：补入可能的中介变量（mediators）和混杂变量（confounders）
  (3) do-calculus 验证：用后门调整/前门调整估计因果效应，核验结论
```

实验覆盖 9 个 LLM × 8 个 benchmark，主要发现：显著抑制「跳步 shortcut」行为，在因果推理和数学推理任务上提升推理忠实度，而不只是答案准确率。

**SCM-GRPO**（2026.05，Qwen3-30B-A3B）：用 GRPO（Group Relative Policy Optimization）做 RL，奖励函数包含三项：

```
R = R_c（准确性）+ R_s（结构合规性）+ R_l（链路长度惩罚）
```

核心发现：推理链长度与准确率呈**倒 U 型**关系——链过短缺失推理步骤出错，链过长引入噪声同样出错。RL 让模型学会在给定任务难度下的最优链长。如果不加 R_l 约束，模型倾向于生成冗长推理链以覆盖更多 case。

**CauCoT**（ICLR 2026 在审）：不改变训练目标，而是在推理后做步骤级因果纠错——定位 CoT 里的因果错误节点（用 CACE，因果平均效应指标评估每步），迭代替换直到推理链因果合规。同时发布了配套 benchmark CRBench（专门测 CoT 里的因果错误）。

### 推理 Trace 的因果效力研究

2025.03 arxiv 的一个重要发现，影响的是训练数据设计层面而非推理技术：

**发现**：CoT 内容对模型泛化行为有独立的因果效力，和最终答案无关。在保持答案相同的情况下，改变推理路径（恶意推理 / 误导性推理 / 顺从推理）训练出来的模型，表现出截然不同的泛化行为，且这种行为在关闭 CoT 输出后依然持续——说明推理内容被内化进了权重，不只是表面文本。

**工程含义**：训练数据里的 CoT 质量直接影响模型的因果推理能力，不能只靠「最终答案正确」来筛训练数据。这是当前 RLHF 数据标注中普遍忽视的问题。

## 外部集成路线：运行时注入因果结构

外部路线不改变模型，而是在推理时把因果知识作为结构化数据提供给模型。核心优势：因果图可以随领域知识更新，不需要重训。

### Causal RAG：给检索流水线加上因果骨架

标准 RAG 的问题：按语义相似度召回的文档只知道「和这个问题相关」，不知道「在因果链上处于什么位置」。Causal RAG 的改造点在于把 DAG 图遍历加入检索路径：

```
标准 RAG 流程：
  查询 → 向量相似 → 召回文档 → 注入 context → 生成

Causal RAG 流程：
  查询 → 向量相似（粗筛）
       → 因果三元组匹配（识别查询对应的因果节点）
       → DAG 路径遍历（沿因果链召回上游原因 + 下游结果）
       → 因果 Rerank（按与查询的因果关联度重排）
       → 注入「因果链 + 文档」的结构化 context → 生成
```

主要框架对比：

| 框架 | 因果图构建 | 检索策略 | 附加能力 |
|------|---------|---------|---------|
| **CausalRAG**（arxiv 2025.03） | LLM 零样本抽取因果三元组 → DAG | 路径检索 + 因果 Rerank | 基础框架，开源 |
| **CC-RAG**（UIUC 2025.06） | GPT-4o 零样本 ⟨cause, relation, effect⟩ 三元组 | 正向 + 逆向链路遍历 | 主题级因果图（ThemeKG 扩展） |
| **NeuroCausal-RAG**（2025.04 生产部署） | NetworkX + Neo4j 持久化 | N 跳检索 + 桥接文档 | 矛盾检测、时序推理、实体链接、SQLite 持久记忆 |

所有框架的共同瓶颈：**因果三元组抽取质量**——LLM 零样本抽取的因果关系存在误识别（把时序关系、定义关系当成因果），且跨文档的因果一致性难以保证。NeuroCausal-RAG 加了矛盾检测部分解决了这个问题。

### CIVeX：工具调用的因果验证层

2025.05 提出的框架，核心论点：**工具调用 ≠ 因果干预**。

标准 Agent 在调用工具时，只验证「工具参数合法吗、API 能跑通吗」，不验证「这个行动对系统状态的因果效应是否可识别、风险是否在接受范围内」。CIVeX 在执行层前插入因果验证：

```
Agent 提出工具调用
    ↓
映射为结构因果查询：E[Y | do(T=t)]
    ↓
在已承诺的 action-state DAG 上检查识别性
（后门调整 / 前门调整 / 工具变量）
    ↓
四种裁决：
  EXECUTE   — 因果效应可识别，LCB（置信下界）≥ 风险阈值
  REJECT    — 可识别，但效应估计不达标
  EXPERIMENT — 不可识别，需要先做受控实验再决策
  ABSTAIN   — 无法识别，且无法安全实验
```

每个裁决附带「因果证书」：图承诺 + 识别论证 + LCB + 数据溯源 + 风险上限，全链路可审计。

对抗性测试发现：在系统性混淆条件（adversarial confounding）下，Claude Opus 直接做工具调用的效用降至 CIVeX 的 74%——因为 LLM 的自然语言因果判断会在对抗条件下退化，而 CIVeX 的图级识别性检查不退化。

### CausaLab / ORCA：因果发现型 Agent

更进一步——不是让 Agent 利用已知因果结构，而是让 Agent 主动**发现**隐藏的因果结构：

**CausaLab**（2025.05）：把 Agent 放入隐藏 SCM 的交互环境，Agent 通过真实干预（而非文本问答）来学习因果图，再把学到的机制迁移到新实例。解决的问题是「因果鹦鹉」——模型背了因果词汇但面对新隐藏图结构就失效。

**ORCA**（CHI 2026）：多 Agent 因果分析框架，三个专职 Agent（数据探索 / 因果发现 / 效应估计）由 Orchestrator 维护跨阶段一致性，引入人工检查点让分析师在关键节点审批因果假设，而非完全自动化。

## 两条路线的权衡

| 维度 | 内部路线（改权重） | 外部路线（改系统） |
|------|----------------|----------------|
| 因果知识更新 | 需要重训 | 实时改图，零成本 |
| 推理透明度 | 权重里难以检查 | 因果路径可审计、可溯源 |
| 领域适配成本 | 需要领域因果数据做 fine-tune | 需要领域因果三元组抽取 |
| 通用推理能力 | 可泛化到新图结构 | 受限于图的覆盖范围 |
| 当前成熟度 | ICML/ICLR 论文阶段 | 有生产部署案例 |
| 核心失败模式 | 训练数据中干预样本稀缺 | 因果三元组抽取质量参差 |

两条路线不互斥，且出现融合趋势：用内部路线训练出更强的因果推理底座（更好地利用外部提供的因果 context），再用外部路线注入领域特定、实时更新的因果结构。CIVeX 的「工具 = 干预」思想可以作为 CausalRAG 检索结果的使用前验证层。
