# 余弦相似度（Cosine Similarity）

> [!tip] 核心本质
> **余弦相似度**衡量两个向量**方向**是否接近：对同维向量 A、B，用点积除以两向量模长之积，得到 **-1～1** 的分，越接近 1 越相似。它忽略向量「有多长」，适合「文本 embedding 里方向≈语义」的常见假设。Dense 检索、语义去重、Skill 描述撞车检测都依赖它；大规模检索时由 [[ann]] 近似最近邻，目标函数常为余弦距离或归一化后的内积。应用编排（混合召回、阈值）见 [[retrieval-pipeline]]。

## 生命周期与演进

**当前定位**：向量检索默认相似度度量；入库 L2 归一化后常与**点积**等价，工程上更省算力。

**预期寿命**：长期稳定。定义来自线性代数，不依赖特定 embedding 模型；换模型须重建索引，但公式不变。

**近期演进**：向量库统一暴露 `cosine` / `l2` / `dot_product` 配置；多语言 embedding 仍用同一套度量。

**终极威胁**：若业务语义强依赖向量模长，纯余弦会丢信息；此时需未归一化内积或混合特征。完整多度量选型指南待 Phase 2（`similarity-metrics` 类节点足够多后再写）。

## 为什么关心「方向」

[[bm25]] 擅长错误码、API 名等**精确词匹配**，但「汽车」搜不到只写「车辆」的段落。Embedding 把语义压进向量后，检索变成「找离查询向量最近的文档向量」——「最近」须先定义**距离或相似度**。余弦相似度是其中最常用的一种：两支箭头同向但长短不同，语义上常表示同一主题、强弱不同；若用欧氏距离，长向量可能仅因「离原点远」被判不相似。

向量从哪来、训练动机见 [[embedding]]；**双塔** 检索里 query 与 doc 各自编码后算 cos(q,d) 取 Top-K，架构与度量选型见 [[bi-encoder]]；全链路见 [[rag]]、[[retrieval-pipeline]]。

## 公式与符号

对两个向量 **A**、**B**（维数相同，例如各 1536 维）：

```
cos(A, B) = (A · B) / ( ||A|| × ||B|| )
```

| 符号 | 含义 | 直觉 |
| --- | --- | --- |
| **A · B** | 点积：对应维度相乘再相加 | 两向量是否「朝同一侧」分量多 |
| **\|\|A\|\|** | L2 模长：各维平方和再开方 | 箭头有多长 |
| **×**（分母） | 两模长相乘 | 把点积按长度拉平，避免长向量天然占优 |
| **cos(A,B)** | 两向量夹角的余弦 | 1 = 同向；0 = 垂直；-1 = 反向 |

取值范围：常见非负文本 embedding 下，相似度多在 **0～1**；完全相反可为负，检索里少见。

### 手算示例

A = [3, 4]，B = [6, 8]（与 A 同向，更长）：

1. 点积：3×6 + 4×8 = **50**
2. 模长：‖A‖ = **5**，‖B‖ = **10**
3. 相除：50 / (5×10) = **1.0** → 完全同向

若 B = [4, -3]（近似垂直），余弦接近 **0**。

## 归一化与点积等价

若先把每个向量 **L2 归一化**为长度 1（各分量除以 ‖v‖），则 ‖A‖ = ‖B‖ = 1，公式退化为：

```
cos(A, B) = A · B
```

许多向量库默认「入库归一化 + 查询用点积」，排名与余弦一致、延迟更低。实现上即点积除以两模长之积（与 [[embedding]] 中示例一致）。

## 双塔检索中的应用

[[bi-encoder|双塔（Bi-Encoder）]] 粗排的标准流程是：**离线** 对 doc 向量 L2 归一化入库，**在线** 对 query 同样归一化后算 cos(q,d)（或与余弦等价的点积），再经 [[ann]] 取 Top-K。此处公式不变，双塔语境下的差异在于：

- **分数是排序键，不是概率**：训练用对比损失塑造空间，0.85 与 0.90 的绝对差无通用语义，只在同索引、同模型内比相对排名。
- **对称与非对称**：DPR 类模型用不同 Encoder 出 q、d，但 **仍须同维、同一训练空间** 才能算 cos。
- **与精排分工**：cos 高只说明「向量方向接近」，不保证否定、数字正确——Top-K 仍常送 [[cross-encoder]] 重打分。

完整链路、对称/非对称表、训练目标与误区见 [[bi-encoder]]。

## 与 ANN、混合检索的关系

上亿向量时不会暴力算完所有 cos，而用 [[ann]]（HNSW 等）**近似**最近邻；索引优化的目标常为余弦距离或等价内积。

单路余弦对同义改写友好，对专有名词弱；工业 RAG 普遍 **BM25 + Dense**，分数尺度不同，用 [[rrf]] 融合排名而非直接加权分数。勿单独迷信绝对分：相似度完全依赖 embedding 模型；分数只在**同索引、同模型**内有意义。

---

## 边界与误区

- **不是理解语义本身**：换模型，分数与排名可能大变。
- **不能替代关键词路**：CVE、ORA 错误码等仍靠 [[bm25]]。
- **高维直觉会骗你**：维数上千时全库余弦常偏高，宜看相对排名或分位数，而非死记 0.9。
- **余弦距离 vs 余弦相似度**：距离常定义为 `1 - cos(A,B)`，越小越相似；与相似度符号勿混。

## 与 L2、点积的简要对比

| 度量 | 核心问题 | 是否看向量长度 | 检索常见度 |
| --- | --- | --- | --- |
| **余弦相似度** | 方向是否一致 | 否（分母已归一化） | 极高 |
| **欧氏距离 L2** | 直线距离是否近 | 是 | 高（向量已归一化时与余弦排序常一致） |
| **点积（内积）** | 未归一化时长度也加分 | 是 | 高（归一化后与余弦等价） |
